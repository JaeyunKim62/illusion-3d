# What We See Is Not What Exists: A Perceptual Twin Room

KAIST 3D Rendering Contest write-up draft

Teammate(s): Jaeyu Kim

## 1. Description

This project is a browser-rendered projective illusion scene. From one fixed reference camera, the viewer sees the phrase `WHAT WE SEE`, a normal-looking rectangular room, and two spheres that appear to have intentionally different image sizes. When the render camera moves sideways, the scene reveals that the apparent room and text are not ordinary geometry: their physical 3D positions were generated by back-projecting a desired 2D percept through the reference camera.

The central theme is:

```text
WHAT WE SEE != WHAT EXISTS
```

The scene is not a 2D illustration mapped onto a plane. It is a procedural 3D construction whose vertices and text pieces satisfy reference-camera projection constraints. The final 10-second video is designed to first show scattered physical geometry, then align to the perceptual target, then reveal the distorted physical twin with technical overlays.

## 2. Contest-rule posture

The implementation follows the KAIST 3D Rendering Contest constraints as a rules-first design requirement:

- Final rendering is done in the browser with WebGL/Three.js.
- No Blender rendering is used.
- No commercial or closed-source 3D tools are used.
- No external 3D assets, meshes, scans, or model files are imported.
- Geometry, text masks, checker materials, labels, camera paths, and overlays are generated procedurally from source code and `scene_config.json`.
- The intended export targets are `representative.png` at 1920x1080 or smaller and under 5MB, and `output.mp4` at 10 seconds or shorter, 1920x1080 or smaller, and under 50MB.

## 3. Technical aspects

### 3.1 Reference-camera inverse projection

The course camera model maps a 3D homogeneous point `X` to an image point `x` using

```text
x = K [R | t] X = P X
```

This project uses the inverse direction during generation. For each desired image-space point `x_i`, it constructs the corresponding reference-camera ray and places a physical 3D point on that ray at a selected depth `lambda_i`:

```text
d_i = R^T K^-1 x_i
X_i = C + lambda_i d_i
```

where:

- `K` is the reference-camera intrinsic matrix.
- `R` is the reference-camera rotation.
- `C` is the reference-camera center.
- `x_i` is a 2D target point in normalized device coordinates.
- `lambda_i` is the chosen depth along the ray.
- `X_i` is the generated physical 3D point.

In the code, `src/main.ts` implements this with `THREE.Vector3.unproject(camera)` in `backprojectNDC()`.

### 3.2 Anamorphic text

The phrase `WHAT WE SEE` is drawn into an HTML Canvas 2D mask. The generator samples bright pixels from that mask, converts each sample to a reference-camera NDC point, back-projects the point to a seeded random depth, and places a small plane there. Each plane is oriented toward the reference camera and scaled with depth so that its apparent size stays roughly constant from the reference view.

Because the depth values differ, the same pieces look scattered and non-text-like from an off-axis camera, but they form readable text from the reference camera.

### 3.3 Distorted room mesh

The perceived room is defined first as 2D screen-space corners: an outer rectangle and a smaller inner rectangle. Each corner receives an intentionally asymmetric depth. Back-projecting those 2D corners creates a physically warped set of 3D vertices. The resulting wall, floor, ceiling, and back-wall quads project back to a normal-looking room only from the reference view.

This uses polygon mesh primitives: vertices, edges, and faces are generated directly in code. Procedural checker materials emphasize perspective cues without importing texture assets.

### 3.4 Same-size spheres

Two spheres use the same physical radius but are placed at different depths along reference-camera rays. This reinforces the difference between physical equality and perceptual size in the rendered image.

### 3.5 Reprojection metric

For generated text points, the app projects each physical point back through the reference camera and compares the result to the intended 2D target. The viewer HUD displays mean reprojection error in pixels. This makes the illusion measurable rather than purely hand-tuned.

### 3.6 Viewer overlays

The browser viewer includes debug/communication overlays:

- Ghost perceived room: a normal rectangular wire box representing what the viewer perceives.
- Projection rays: sampled rays from the reference camera to generated geometry.
- Reference frustum: the camera helper for the projection constraint.
- Labels: `Physical Twin`, `Perceptual Twin`, `Reference Camera`, and same-size sphere explanation.

The overlay control separates `Off`, `Ghost`, `Rays`, and `All` so the final judging view can stay readable while the technical explanation remains inspectable.

## 4. Reproduction steps

```bash
npm install
npm run dev
# open http://127.0.0.1:5173
npm run harness
```

Representative image:

1. Open the app in Chromium or Edge.
2. Choose either `기준 시점` for a clean perceptual image or `왜곡 reveal` for the technical reveal.
3. Press `PNG 캡처` to download `representative.png`.

Video export:

1. Press `10초 WebM 녹화`.
2. Keep the browser tab focused until `output.webm` downloads.
3. Convert to MP4:

```bash
ffmpeg -y -i output.webm \
  -t 10 \
  -vf "scale='min(1920,iw)':-2,fps=60,format=yuv420p" \
  -c:v libx264 -preset slow -crf 20 -movflags +faststart \
  output.mp4
```

4. Validate size and duration:

```bash
ffprobe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 output.mp4
```

If the result is over 50MB, increase CRF, for example to `-crf 23`.

## 6. Limitations and next improvements

- The current prototype communicates the inverse-projection idea clearly, but the `WHAT WE SEE` text can still look fragmented at the left edge from some viewport sizes.
- The right-side control panel can require scrolling on short displays.
- Final submission still needs an actual MP4 export and file-size check from the chosen browser recording.
- A final pass should capture a representative PNG and output MP4, then verify duration, resolution, and file size.
